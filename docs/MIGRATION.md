# Migrating `or.log` v0 → v1

**Status:** implemented. The frozen fixtures under `tests/fixtures/` pin both
directions, and `internal/fixture` is the byte-identity court.

## 1. The wire difference

The format version lives in the **genesis payload** — the payload of the first
committed record, `VOLUME_GENESIS`. A reader decides compatibility from the log
itself, never from a rebuildable sidecar.

Genesis payload, little-endian:

| Offset | Width | Field | Present |
| ---: | ---: | --- | --- |
| 0 | 16 | volume `uuid` | always |
| 16 | 8 | `segment_size` | always |
| 24 | 2 | `format_version` | **only** in the versioned (≥ 26-byte) layout |

- **v0** — a **24-byte** genesis (`uuid ‖ segment_size`), version inferred `0`.
- **v1** — a **26-byte** genesis (`uuid ‖ segment_size ‖ format_version`),
  version `1`.

The only difference is the trailing 2-byte version field; **every transaction
record is byte-identical between the two**, so a v1 committed root is exactly
**2 bytes larger** than the equivalent v0 root. This is asserted by
`TestVersionedGenesisIsExactlyTwoBytesLarger`.

## 2. Reader algorithm

```
len = payload.length
if len < 24:     reject (corrupt: too short)
if len == 24:    format_version = 0                 # legacy: field absent
elif len >= 26:  format_version = u16_le(payload[24..26])
else:            reject (corrupt: length 25)
if format_version > LOG_FORMAT_VERSION:
    reject (UnsupportedFormatVersion)               # never guess
accept                                              # 0 <= version <= current
```

Enforced at open (`volume.Open` parses the genesis before returning). The same
rule applies to `volume.meta`'s `format_version`: a known version ≤ current is
accepted; a higher one is refused.

## 3. Compatibility matrix

| Frozen log | v0 reader | v1 reader (current) |
| --- | --- | --- |
| v0 (24-byte genesis, version `0`) | reads | **reads** — replays, verifies, reports `format_version = 0` |
| v1 (26-byte genesis, version `1`) | must not guess — treat as newer and refuse | **reads** — reports `format_version = 1` |
| v>1 (unknown) | — | **refuses** `UnsupportedFormatVersion` |

A v1 reader must never interpret a versioned genesis as if the payload ended at
24 bytes, must never fold the trailing bytes into `segment_size`, and must never
truncate, rewrite, or "repair" a record, nor mount on a guess.

## 4. Fixtures

Location: `tests/fixtures/{legacy_v0,current_v1}/`. Each is a minimal but
semantically valid volume: `volume.meta` plus a single
`or.log/0000000000000000.seg` containing a `VOLUME_GENESIS` followed by two
committed transactions (create `hello.txt`; write `hello, orfs\n`). Only the
committed bytes are included; the derived sidecars (`index/`, `.or_bloom/`,
`commit.watermark`) are deliberately absent — they are rebuildable, not part of
the frozen identity.

Regenerate (they are never edited by hand):

```sh
ORFS_GENERATE_FIXTURES=1 go test ./internal/fixture/ -run TestGenerateFixtures
```

The court (`internal/fixture/format_compat_test.go`) asserts: byte-identity
against a fresh build; replay equivalence (the logical content is
`hello, orfs\n`); the reported `format_version`; the exact 2-byte delta between
v0 and v1; and the unknown-higher-version refusal.

> **Provenance.** These fixtures are produced by the deterministic Go builder
> (`internal/fixture`), not by the Rust reference. The Rust reference ships its
> own byte-frozen pair at `.reference/OrFS/tests/fixtures/{legacy_v0,current_v1}`
> (regenerated by `cargo test --test format_compat -- --ignored
> generate_fixtures`); the cross-language court (`scripts/container-crosslang.sh`,
> phase 38) now **uses those Rust bytes as ground truth**: it builds the Rust
> `orfs` crate, proves Go replays them to exactly `hello.txt` containing
> `hello, orfs\n`, and proves the Go codec re-encodes every Rust frame
> byte-for-byte. It also reads the Go fixtures with the Rust binary. The two
> builders' bytes still differ for the same fixture — the Go builder picks its
> own volume UUID, segment size, inode timestamps, `TX_BEGIN` advisory
> `expected_*` values, and record-header inode stamps — which is recorded as a
> finding in `evidence/correctness/crosslang.json` rather than hidden.

## 4a. Cross-language interchange and the compatibility profile

Reading is symmetric for every record type the reference registry defines
(`0x0001`–`0x0015`): the court mounts a Rust-written volume in Go, and a
Go-written volume in Rust, with identical read-backs.

Writing is **not** fully symmetric by default. This build's native profile emits
two mandatory record types the reference does not define (`docs/ON_DISK.md`
§3.3): `CTIME_UPDATE` (`0x0017`) for hard link, rename-overwrite, chmod and
unlink, and `MKNOD_CREATE` (`0x0016`) for special files. A reference reader
refuses such a volume with `unknown mandatory record type 0x0017`.

Moving those types into the format's *optional* space (bit 15) was measured
against the real reference and does **not** help. The reference's replay
(`Index::from_log` → `apply_record`, reached by both `verify --deep` and `mount`)
calls `Record::known_type()`, which hard-errors on an optional-unknown record
(`record type 0xNNNN is optional and has no known semantics`). Only the
reference's log *scan* counts an optional record into the `TX_COMMIT` bracket;
its replay does not skip it. So optional buys nothing here.

The supported interchange profile is therefore explicit. Under the
**compatibility profile** the writer emits only the reference registry and
semantics:

- `CTIME_UPDATE` is suppressed; `ctime` is derived from `mtime` on
  `INODE_SETATTR`, exactly as the reference does — a metadata-only change
  (chmod/chown/link/unlink) therefore does not advance `ctime`.
- `MKNOD_CREATE` is never emitted: creating a special file (fifo/char/block/
  socket) is refused with `EOPNOTSUPP`. Optional-skipping it cannot work — the
  following `DENTRY_ADD` would name an inode the reference never created — and the
  reference has no way to represent a special-file inode.

Select it per process or per mount:

```sh
ORFS_COMPAT=1 orfs mount <backing> <mountpoint>
orfs mount --compat <backing> <mountpoint>   # --compat=false overrides ORFS_COMPAT
```

Programmatically: `volume.WithCompat()` / `volume.WithCompatProfile(bool)`.

**The default is the native profile** — full POSIX ctime semantics and special
files. The compatibility profile is opt-in because it gives those up; making it
native by default would silently lose POSIX `ctime` correctness. A volume may mix
profiles over time (each `mount` chooses), and reading is unaffected in either
direction: the Go reader always accepts every type it knows, from any writer. The
cross-language court (`scripts/container-crosslang.sh`) runs the Go writer in the
compatibility profile, and additionally asserts — as an explicit gate rather than
a silent pass — that the native profile is refused by the reference. See
`evidence/correctness/crosslang.json`.

The Go reader also treats `TX_BEGIN`'s advisory `expected_record_count == 0` as
“unset”, exactly as the Rust verifier does.

## 5. Adding a future version

1. Register it in `docs/ON_DISK.md` §6 (and this file).
2. Bump `record.FormatVersion`, keeping all older versions accepted.
3. Add a fixture variant; generate bytes; extend the court.
4. Commit the frozen bytes and update the provenance note above.

There is no destructive upgrade path, by design: a newer binary reads old bytes
and, if it writes, appends new records at the committed root. The old bytes stay
authoritative.
